## مرحله ۴ — چه باید کرد (به ترتیب اثر)

شکست‌های مشخصی که #19 ثبت کرد و هر کدام باید با اجرای
`NM_THIRD_PARTY=1 cargo test -p neuromesh-context --test third_party_gold -- --nocapture`
قبل/بعد دیده شود:

1. **decoy هم‌نام در مسیرهای مختلف:** `nano_char_vocab` recall ۰ — سه `prepare.py`؛ کلمات مسیر
   (`shakespeare_char`) در prompt باید مسیر را steer کنند. (`resolve_file_hint`/`path_hint_matches`)
2. **`vit_sincos` recall ۰:** `posemb_sincos_2d` resolve نمی‌شود؛ ۶ فایل غلط از ۶۰ فایل هم‌شکل.
   کاندید اصلی reranker + tantivy (BM25 دست‌ساز ضعیف است).
3. **frontend برای سؤال backend (FastAPI):** فایل‌های `.tsx`/`types.gen.ts` در packet — هرس مشروط
   به query / زبان.
4. **sidecar Physarum مصرف‌کننده‌های هم‌ردیف را می‌آورد:** express همه‌ی `lib/*.js`، nanoGPT
   `bench.py`+`sample.py`. `MAX_PHYSARUM_SIDECAR_FILES=3` و بدون امتیاز query.
5. **fold policy:** strict روی ریپوی واقعی ۱۲/۲۱ (`GPT.forward` fold می‌شود وقتی prompt فقط
   «model forward» می‌گوید).
6. **`style_routing::style_noise_penalty`** اسم فایل‌های فیکسچر را هاردکد دارد — حذف/عمومی شود.
7. **marker fold کوتاه‌تر:** fold-not-delete روی `handle_tool_call_intent` +۴٫۸٪ توکن؛ قانون
   «foldی که چیزی ذخیره نمی‌کند نزن» تست‌های ریز skeleton را می‌شکست.

هدف عددی مرحله ۴: precision ریپوهای واقعی ۰٫۱۴۶ → ≥۰٫۵، فایل ممنوع ۱۳ → ≤۳،
oracle ۱۴/۲۱ → ≥۱۹/۲۱؛ و `precision_min` گیت ریلیز ریپو ۰٫۳۸۳ → ≥۰٫۷۳.
هر بهبود = بالا بردن ثابت‌های ratchet در `third_party_gold.rs`.

## ابزارهای هر مرحله

```bash
bash scripts/ci-local.sh                         # آینه‌ی کامل CI (NM_THIRD_PARTY=1 → گلد واقعی هم)
```

diff کن؛ عدد بده نه ادعا؛ ثابت‌های ratchet هیچ‌وقت پایین نمی‌آیند.
